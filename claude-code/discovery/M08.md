The local clone of `deepidv-chain-node` is also a 0.0.1 placeholder, so M07's actual built surface is not yet present locally. The user prompt for M08 supplies the canonical SDK shape directly:

- API client over `httpx` (sync `Client`, async `AsyncClient`).
- Pydantic v2 models, snake_case field names.
- Crypto primitives: JCS canonicalization (RFC 8785), envelope hash, STH hash, manifest checksums (sha256sum-compatible).
- Offline bundle verify with the 5-of-6 contract (TSA tokens skipped, never silently treated as valid).
- ECDSA P-256 verification via the `cryptography` library.
- SSE streaming via `httpx`.
- Cross-language parity tests against the same fixtures used in `shared-deps` / M07.

Deviations from the original runbook M08 spec:

| Runbook M08 | This build | Why |
| --- | --- | --- |
| Zero-runtime-dep sync client (`urllib`) | `httpx` for sync + async | Aligns with M07's richer surface (registry pagination, SSE, segments, consistency proofs). The original `urllib` design predates the M02..M05 API surface. Documented in Section 6 of the Luka handoff. |
| `Chain` class with `mint/verify/revoke` | `Client` / `AsyncClient` with read-only registry surface + offline `verify_bundle` | The mint/revoke surface belongs to issuer-key-holding callers and is gated behind tenant API keys not yet provisioned. v1 ships the public read + offline verify surface that matches `proof.deepidv.com`. |
| `dpiv` CLI | Deferred | Examples scripts cover the smoke-test surface; CLI lands in 1.1 once stream and verify shapes have soaked. |
